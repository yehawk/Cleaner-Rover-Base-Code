# Cleaner-Rover-Base-Code
A base code for a joystick controlled rover, aimed to target working class alleys and detect specifically cigarettes (or other smaller, "white" trash) on the ground. 

Video Demo: https://youtu.be/8gyM98rbsZo

Description:
The following three files are the base codes for a Raspberry Pi MicroPython powered cleaner rover. Inspired after seeing the lack of cleaning in working class alleyways in my city (especially so with cigarette tossed on the ground which are difficult to clean), I decided to create a cleaner rover with joystick controls, and an autonomous arm control system! If the machine detects a white object in it's vicinity, the arm is immediately activated and goes through with the action of picking the cigarette up and tossing it into the bin attached to the rover. Although this is not the exact code used to power the electronic parts, it is a very close simulation of how the electronic compartments will act based on a simulation web program called "Wokwi." Therfore, I had to make a lot of modifications and adjustments to import different parts that were not supported fully. Parts of the code (which are mentioned throughout the code with comments) are imported from a core.electronics tutorial on rover machines.

Rover controls The rover.py file contains the python code for basic rover controls. This includes back and forth speed controls, along with an angle controls that allow the machine to move left and right based on a 180 degree rotation system. Because I cannot visualize DC motor functions on Wokwi, I connected the speed control with Green LED lights, and the angle control with Red LED lights. When the program begins running, you'll see the right gear turning as the Green LED turns on. The Red LED only turns on when the gear reaches a negative angle, assuming deacceleration is followed by an angle shift. In reality, these LEDs will be replaced with DC motors that actually powers and controls the movement of the rover.

Joystick controls The joystick.py file contains the python code for joystick functions that control the rover's movements. This includes back and forth motions involving the back and forth swipping on a traditional, analog joystick system, and turning/swerving based on left and right controls on the joystick. I considered taking out the OLED display from the original code, as I was not sure if I was going to implement the same function in my rover design, but I figured it was good practice how to accomodate and modify electronics codes for less detailed online simulation programs. The motion is registered on a two dimensional axis basis; X axis and the Y axis, calculates the radians of movement range and also uses trignometry to accurately convey distance. To use this simulation, you must have your terminal open. When the joystick is toggled, the terminal will display numerical values of the movement coordinates. Again, this was an adjusment I had to make because there was no realistic way for me to visualize movement without actually buying the electronic parts and connecting them to a physical machine.

Robotic arm controls The robotic_arm.py file contains the python code for robotic arm controls that actually pick up the trash. This includes 1. a camera sensor that detects a white object, 2. a conditional loop that activates the arm movement when the sensor picks up white, and 3. an arm movement sequence that picks up and throws the garbage into the disposal area. I deployed a camera sensor (since Wokwi doesn't support a color based visual sensor), and manually programmed it so it detects specific RGB level combinations that results in a "white" color. Then, I used 4 different servos that will simulate "joints" - base, shoulder, elbow, claw - and coded them into a specific sequence such as: bend arm -> grip with claw -> lift -> rotate and release etc, depending on which servos or "joints" each step uses. Then, I put a conditional to make sure the sequence activates when the camera picks up white. Since this had no base code and I had to create multiple 3D models to visualize the joints and structures, this was easily the most difficult part of the project.
